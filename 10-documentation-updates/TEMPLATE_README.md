# Documentation Updates Templates

This folder contains CodeRabbit configuration templates and example documentation for documentation-focused pull requests.

## Contents

- `coderabbit.yaml` - CodeRabbit configuration for documentation update reviews
- `README.md` - Example comprehensive README documentation
- `API-documentation.md` - Example API documentation
- `API-EXAMPLES.md` - Example API usage examples

## Usage

Use these templates when creating pull requests that update documentation to ensure comprehensive review coverage of:

- Content accuracy and completeness
- Clear and concise writing
- Proper formatting and structure
- Code examples and snippets
- Cross-reference validity

## Best Practices

- Write for your target audience (beginners vs experts)
- Use clear, concise language
- Include practical examples and code snippets
- Maintain consistent formatting and style
- Keep documentation up-to-date with code changes

## Documentation Update Checklist

### Content Quality
- [ ] Information is accurate and current
- [ ] Language is clear and concise
- [ ] Target audience appropriately addressed
- [ ] Technical concepts explained clearly
- [ ] Examples are practical and working

### Structure & Organization
- [ ] Logical information hierarchy
- [ ] Consistent formatting and style
- [ ] Proper headings and subheadings
- [ ] Table of contents (for long docs)
- [ ] Cross-references and links work

### Code Examples
- [ ] Code snippets are tested and working
- [ ] Examples show real-world usage
- [ ] Multiple language examples (if applicable)
- [ ] Error handling demonstrated
- [ ] Best practices illustrated

### Accessibility
- [ ] Alt text for images and diagrams
- [ ] Descriptive link text
- [ ] Proper heading structure
- [ ] High contrast for readability
- [ ] Screen reader friendly formatting

## Documentation Types

### API Documentation
- **Purpose**: Endpoint reference and usage
- **Includes**: Parameters, responses, examples
- **Tools**: OpenAPI, Swagger, Postman
- **Format**: Interactive documentation

### User Guides
- **Purpose**: Step-by-step instructions
- **Includes**: Tutorials, walkthroughs, FAQs
- **Tools**: GitBook, Notion, Confluence
- **Format**: Narrative documentation

### Technical Specifications
- **Purpose**: Detailed technical information
- **Includes**: Architecture, protocols, schemas
- **Tools**: Markdown, AsciiDoc, LaTeX
- **Format**: Formal documentation

### Code Comments
- **Purpose**: In-code documentation
- **Includes**: Function docs, inline comments
- **Tools**: JSDoc, Sphinx, Javadoc
- **Format**: Generated documentation

## Writing Guidelines

### Style
- Use active voice when possible
- Write in present tense
- Be concise but complete
- Use parallel structure in lists
- Maintain consistent terminology

### Structure
- Start with overview/introduction
- Organize by user goals
- Use progressive disclosure
- Include next steps/related topics
- End with troubleshooting/FAQ

### Maintenance
- Regular review and updates
- Version control integration
- Automated testing where possible
- Community feedback incorporation
- Deprecation notices for old content
